# Listi usability backlog

Reviewed against installed 0.38.0-20 (deb02af), Haiku beta6. These are proposed improvements, not reproduced data-loss bugs or implemented changes. Evidence numbers refer to the installed desktop journey screenshots for request 28102. No new physical-device or novice-user test was performed. P1 = prioritise because a misunderstanding can affect files; P2 = common task friction; P3 = discoverability or convenience.

## First review

- [ ] P1 **Show the copy/move destination at the action.** The pane outline and direction line work, but the buttons are far from the path (01, 04). In either direction, including narrow panes and two folders with the same name, a user should be able to identify the destination before acting. Preserve shortcuts and avoid an extra confirmation for normal copies.
- [ ] P1 **Separate one-file conflict choices from batch choices.** Replace and Replace all are peers in a row of six (20, 21). Group by outcome; explicitly opt in to applying a decision to remaining conflicts. Verify a single Replace does not decide the next conflict; preserve the Keep both name preview.
- [ ] P1 **State the file outcome before diagnostic details.** The physical USB screenshot from an older build showed Queue finished alongside a staging-path error. On a failed, partial or uncertain copy, name the affected item and destination and offer an appropriate next step. Do not promise that nothing changed unless verified. Keep exact diagnostics available. Physical follow-up: a failed Copy banner remained beside a successful Convert image result (1 completed, 0 errors), with the JPG visible on the stick. Clearly attribute a retained error to its original job rather than implying that conversion failed.
- [ ] P2 **Distinguish filtering the current folder from searching subfolders.** Label the scope at each entry point; keep folder, name and Search prominent, advanced criteria accessible (04, 16–19). A person should find a nested match and understand why a pane filter alone cannot find it. Preserve filtered Select All.
- [ ] P2 **Connect automatic history settings to saved versions.** Let users browse the configured pair directly and suggest an unused restore destination (26–29 and automatic-history GUI). Restore must still refuse existing destinations and must not alter the source. Physical feedback after reboot: the Deskbar clock returned, but browsing the configured source gave no visible indication of folder history. Show a discreet, actionable history status in that pane. Distinguish “enabled, no saved versions yet” from versions actually available; open the matching history directly. Verify on navigation between configured and unrelated folders, and after reboot; the clock alone is not evidence of a saved point. The physical Folder history dialog knows the source but opens with a blank History folder field, two empty lists and disabled actions. For a known pair, load its saved versions with zero input: no typing, folder picker or Connect click, including after reboot. Distinguish not connected, store unavailable and connected with no versions. Physical test confirms that the manual History folder field only accepts typed paths and has no Browse control. When manual selection is needed, add a visible “Choose folder…” button beside the field that opens the native Haiku folder picker. Accept selection without typing; cancelling leaves the existing field unchanged.

## Second review

- [ ] P1 **Show where Trash Restore will put the file.** The confirmation promises “original folders” but shows no destination (10; FileOperationFlow.cpp). Preview the original path for one file and destinations for a mixed selection. If unknown or occupied, distinguish that from a successful restore. Keep Cancel safe and never overwrite.
- [ ] P2 **Name the actual folder when creating a new folder.** Duplicate names its containing path, but New folder says only “in the active panel” (02, 06). Show the target folder beside the name field, independent of the unrelated Copy/Move direction banner. Verify in both panes with identical leaf names.
- [ ] P2 **Preview a saved workspace before opening it.** The chooser shows set names, not their contents (22–25; WorkingSets.cpp). On selection, preview window count and panel folders and explain that opening adds windows without replacing the current one. Test with two similarly named sets; do not open windows just to inspect them.
- [ ] P2 **Keep the ordinary ZIP path short.** In the observed expanded archive form, compression, favorite, default, always-ask and encryption compete with name and destination; Extract already has a much simpler form (11, 12). Separate one-off archive choices from lasting preferences. Keep nondefault format/encryption visible in the collapsed summary and preserve existing preferences.
- [ ] P3 **Expose reopening a closed tab near the tabs.** The verified path goes through Window → Folder tabs → Reopen closed tab (13–15; MainWindowMenu.cpp). Offer the same command where tabs are managed, retaining the menu path when the tab strip is hidden. Verify the reopened tab returns to the intended pane.
- [ ] P3 **Make confirmation text match the selection count.** Single-file Trash and Restore prompts say “1 selected entries” (08, 10). Name a single item; give an accurate count and plural for multiple items. Check long filenames, one folder and a mixed selection without changing safe keyboard defaults.

## Physical testing feedback (ongoing)

- [ ] P1 **Copy a Haiku screenshot with image attributes to FAT.** The tester tried the copy shortcut (reported as Alt+Shift+C) and drag-and-drop. Copy reported zero completed and could not preserve Media:Width on the temporary destination. Test both entry points with an attributed PNG on BFS and a FAT target; verify destination bytes and source retention. Distinguish a filesystem metadata limitation from a failed data write; never silently discard metadata or relax Move safeguards.
- [ ] P2 **Explain the red transfer mark.** The tester could not tell why a red line appeared beneath the source PNG after Copy failed. Make the failed operation identifiable without relying on colour alone; distinguish it from selection and from damage to the original.
- [ ] P2 **Check Quick view readability independently of USB.** Text in screenshot previews looked poor; examples show 57% and 47% fit. Compare the same original PNG at fit and 100% against a reference viewer on Haiku, not a Telegram JPEG. Distinguish normal scaling loss from a rendering defect before choosing a fix.

- [ ] P2 **Open detached Einn windows at a compact, Tracker-like size.** Side-by-side physical screenshots of the same home folder (feedback 28132) show Listi opening far wider than its populated columns. When detaching, use a compact initial frame with readable columns and scrolling rather than filling the desktop. Verify on small and large screens, allow manual resizing, and leave the original two-pane window unchanged.

- [ ] P2 **Make Detach to Einn window easier to find.** The command is buried under Window → Folder tabs. Use the concise menu label “Detach tab to Einn window” if the action detaches the current tab; avoid implying that all tabs in the active pane move. Expose the same action directly in Window so it is discoverable even when the tab strip is hidden. Verify it detaches the intended tab without changing existing detach behaviour.

- [ ] P1 **Make selected rows unmistakable in Details view.** After Select same filetype on a PNG, physical feedback was that unrelated rows looked selected. The pane reports 27 of 45 selected; the screenshot does not establish a matching error. Use a mixed-extension fixture to check the actual selected paths separately from rendering. Verify that selected rows are easy to distinguish from alternating row shading and keyboard focus, including in the native light theme, before any bulk operation.

- [ ] P2 **Explain transparency loss when converting to JPEG.** In the physical USB test, the source PNG had transparent areas and the converted JPEG did not. JPEG cannot store transparency; this alone is not a failed write. When converting an image with transparency, show that transparent areas will become opaque, indicate the background colour used and offer PNG to retain transparency. Verify with a transparent PNG without altering the original.

- [ ] P2 **Create a file from the folder background menu.** Right-clicking empty space in a writable folder should offer “New file…”. Ask for a filename and create an empty file in the clicked folder, even if the other pane was active. Verify in an empty folder and in both panes; cancelling creates nothing and an existing name is never overwritten.

- [ ] P2 **Offer a Tracker-style Mini icon view.** Add “Mini icons” to the pane view selector as a distinct choice: small icons with filenames alongside, so more entries fit without the detail columns. Compare against Tracker on the same folder and verify switching views preserves the folder and selection.

- [ ] P2 **Use one status line after a successful copy.** Physical drag-and-drop test: even with Details collapsed, the footer still shows Queue finished, counters and a separate path line. For routine success show one compact line (e.g. “Copied New text file to Downloads”) with Details on demand. Keep the exact paths and counters in the log. Verify file panes reclaim the space, including in narrow windows; failures, partial results and conflicts requiring a decision must remain visible.

- [ ] P2 **Let users choose a containing folder for history restore.** Physical test: the user created a Desktop folder and entered it as the destination; even an empty existing folder is refused because the field names the new copy itself. Let users pick an existing parent, suggest an unused child name and preview the resulting full path. Verify restore creates that child without merging, overwriting, or requiring deletion of the parent.

- [ ] P2 **Restore one file from a saved version.** Physical feedback: restoring the whole folder to a new path worked, but required a workaround. Let the user select a file in the saved contents and restore just that file to a chosen folder, without extracting its siblings. Keep full-folder restore available as a distinct action. Test with a nested file changed since the saved point: the recovered bytes must match the selected version, the current source must remain unchanged, and a destination name conflict must never silently overwrite.

- [ ] P2 **Browse folder history in context.** From the folder background menu, offer a read-only preview in the neighbouring pane or a separate window. A quiet folder-level indicator opens history for the configured source without a path prompt. Browse actual saved points by date using a timeline; make the selected time distinct from the live folder, and return to the previous pane without losing place. Moving in time must never restore files by itself.

- [ ] P1 **Inspector breaks when switching from discarded text edits to a PNG.** Physical report: open Inspector, edit a text file, choose Discard, then select a PNG. The footer shows the new image name and dimensions but the preview is blank with fragments of controls (feedback 28181). Follow-up (28184): selecting a text file afterwards shows its contents, filename and Edit button. Listi continued responding, but the tester also reports white space left around the subsequent text preview. Hiding and re-enabling Inspector via View did not restore normal rendering (28190): a different PNG is identified at 20%, but the preview remains mostly white with a narrow strip visible at the right. Include hide/show and switching between panes in the regression. Compare the same text file before and after Discard → PNG → text at the same inspector width; text, scrollbars and margins should return to the original layout. The cause is unverified. Verify the original text remains unchanged, the image renders and the inspector remains usable when switching back.

## Validate before rollout

Ask a first-time Haiku user to predict a move destination, keep both conflicting files, and restore a trashed file without hints. Record wrong predictions separately from wrong clicks and task completion. Repeat with a keyboard-only user and a narrow window. Scripted success verifies mechanics, not discoverability.
